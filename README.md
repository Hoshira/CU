# Shell Emulator

Эмулятор командной оболочки UNIX-подобной ОС на Python 3.

## Этап 1. REPL

Минимальный прототип: реализован REPL (Read-Eval-Print Loop) с
приглашением к вводу, парсером команд и командами-заглушками.
Большинство команд пока ничего не делают — это заготовки для
следующих этапов.

### Цель этапа

Создать минимальный прототип консольного приложения, в котором
уже поддерживается диалог с пользователем, но большинство
функций реализовано в виде заглушек.

### Возможности

- CLI-интерфейс.
- Приглашение к вводу на основе реальных данных ОС:
  `username@hostname:cwd$`.
- Парсер ввода: разделение строки на команду и аргументы
  по пробелам (множественные пробелы игнорируются).
- Команды-заглушки: `ls`, `cd`.
- Служебные команды: `help`, `exit`.
- Обработка ошибок:
  - неизвестная команда;
  - неверное число аргументов.
- Корректная обработка `Ctrl+C` (не выходит из эмулятора)
  и `Ctrl+D`/EOF (корректное завершение).

### Требования

- Python 3.7+.

### Запуск

Из корня репозитория:

```bash
./run.sh
```

Или напрямую:

```bash
python3 -m src.emulator
```

На Windows:

```bat
run.bat
```

### Команды

| Команда | Описание                           |
| ------- | ---------------------------------- |
| `ls`    | Заглушка: печатает имя и аргументы |
| `cd`    | Заглушка: печатает имя и аргументы |
| `help`  | Список доступных команд            |
| `exit`  | Завершение работы эмулятора        |

### Пример работы

Ниже — типичная сессия, включая обработку ошибок.

```text
$ ./run.sh
Эмулятор оболочки (этап 1). Введите 'help' или 'exit'.
user@host:~$ help
Доступные команды: ls, cd, help, exit
user@host:~$ ls
ls: заглушка
  аргументы: (нет)
user@host:~$ ls -la /tmp
ls: заглушка
  аргументы: -la /tmp
user@host:~$ cd
cd: заглушка
  аргументы: (нет)
user@host:~$ cd /home/user
cd: заглушка
  аргументы: /home/user
user@host:~$ cd a b c
cd: слишком много аргументов
user@host:~$ unknown_cmd
unknown_cmd: команда не найдена
user@host:~$ LS
LS: команда не найдена
user@host:~$
user@host:~$ exit
exit: завершение работы
```

### Обработка ошибок

**Неизвестная команда.** Если введённой команды нет в таблице
обработчиков, эмулятор печатает сообщение в stderr
(`<имя>: команда не найдена`) и **не** завершает работу —
возвращается приглашение.

**Неверное число аргументов.** Для `cd` разрешён максимум один
аргумент. Если передать больше, выводится сообщение
`cd: слишком много аргументов`, и цикл продолжается.

**Пустая строка.** Нажатие Enter без ввода игнорируется —
приглашение печатается снова.

### Ограничения этапа

- `ls` и `cd` — заглушки, реальной файловой системы нет.
- Рабочая директория (`cwd`) в приглашении берётся из реальной
  ОС; команда `cd` её не меняет.
- Нет параметров командной строки — они появятся на этапе 2.
- Нет виртуальной файловой системы — она появится на этапе 3.

## Этап 2 — Конфигурация

Эмулятор принимает параметры командной строки:

| Параметр        | Описание                            |
| --------------- | ----------------------------------- |
| `--vfs PATH`    | путь к физическому расположению VFS |
| `--script PATH` | путь к стартовому скрипту команд    |

При запуске печатается отладочный вывод всех параметров.

### Запуск

```bash
./run.sh --vfs ./vfs_samples/nested
./run.sh --script ./scripts/demo_commands.txt
./run.sh --vfs ./vfs_samples/nested --script ./scripts/demo_commands.txt
./run.sh                                   # интерактивный REPL
```
